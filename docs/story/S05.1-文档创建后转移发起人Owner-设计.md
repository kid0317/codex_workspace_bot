# S05.1：文档创建后转移发起人 Owner

> **状态**：Ready for Delivered audit（2026-07-13；真实 p2p/group Owner 转移与 blocker-only 独立复审均通过；全仓 `-race` 当前受并行 S06 未完成字段改动阻塞）
> **依赖**：S05 已 Delivered；当前 MySQL action ledger、当前 App 的 docx create 权限，以及飞书开放平台已审批的“转移云文档的所有权”或官方列出的等价 Drive scope。若调用身份对新文档没有分享/管理权限，真实接口会拒绝转移。

## 1. 目标与边界

当 `feishu.doc_create_and_announce` 成功创建当前 App 的 docx 文档时，Bot 必须把该**单一文档**的 Owner 转给触发本次 Turn 的飞书消息发起人。p2p 和群聊均以 ingress 的 `sender_open_id` 为唯一候选 Owner；绝不把群 `chat_id`、回复目标、模型参数或任意 tool argument 当作 Owner。

创建文档和向当前会话公告 URL 是主交付；Owner 转移是紧随创建的 best-effort 后处理：转移失败、超时或返回未知时，URL 仍须照常公告，tool result 必须诚实返回 `owner_transferred:false` 及稳定的脱敏 outcome。不得由模型指定 recipient、doc token、App 或凭据。

本 Story 不做：批量/云盘扫描转移、任意文档 owner 转移、分享成员管理、跨 App/跨会话转移、失败自动以新 call 重试，或把 owner open_id / document token 写入普通日志、workflow、Langfuse、`messages` 正文。

## 2. 设计

### 2.1 身份与数据流

`router.Incoming.SenderOpenID` 已经是经过飞书 event 解析和 receipt 持久化的可信发送者身份。Router 必须将其作为 memory-only `worker.ActorPrincipal` 写入每条 `worker.Message`；普通 message Batch 只能合并同一 Actor 的连续消息。`cmd/server` 从 active Batch 的 exact Actor 构造 `feishuaction.Route{OwnerOpenID: ...}`。若 Actor 缺失、为空或一个 Batch 混入多个 Actor，则 document action fail closed，且不得创建文档或调用 Drive。

该身份不来自动态工具参数：`doc_create_and_announce` 参数仍仅允许 `markdown_ref` 和 `title`。

### 2.2 外部调用与可见结果

`feishu.Sender.CreateDocumentAndAnnounce` 在 `Docx.Document.Create` 成功后保留 document ID 仅供当前调用链使用；先按既有规则完成或尝试完成 Markdown block 写入，再在 URL 公告前调用：

```text
POST /open-apis/drive/v1/permissions/{document_id}/members/transfer_owner
  ?type=docx&need_notification=false&remove_old_owner=true
{"member_type":"openid","member_id":"<trusted sender_open_id>"}
```

这样 `remove_old_owner=true` 不会抢先撤销 App 完成 block 写入的权限。无论 Markdown convert/block 写入是否完整，均只发起一次转移并按现有规则公告 URL。结果为：

```json
{
  "url": "https://feishu.cn/docx/...",
  "content_written": true,
  "announcement_outcome": "sent|unknown",
  "owner_transferred": true,
  "owner_transfer_outcome": "transferred|rejected|unknown|not_attempted"
}
```

转移只有明确成功才为 `transferred`。网络错误或响应不完整是 `unknown`，明确 API 拒绝为 `rejected`；它们均不重试、不改变已创建文档的主成功状态。Action ledger 对整个 tool call 保持既有 `(app_id,thread_id,turn_id,call_id)` at-most-once replay：同 callId 重放只返回加密缓存结果，不得再次创建文档或再转 Owner。

### 2.3 可观测性与安全

普通日志、workflow、Langfuse 和 tool 公开结果不得包含 owner open_id 或 document ID；仅记录 action state、`owner_transfer_outcome` 和 salted document digest。Drive token、Authorization header、响应正文不得落盘。发送者身份仅在 active Worker/Route 内存中存活，并用于 Action 的当前调用。

## 3. 验收场景

| 编号 | Given / When / Then |
|---|---|
| S05.1-AT-01 | Given p2p 或 group 的 document tool call，When document create succeeds，Then transfer request 的 member_id 等于触发消息的 sender open_id；群 chat_id 和 ReplyTarget 不得进入该 request。 |
| S05.1-AT-02 | Given document create succeeds而 owner transfer is rejected/unknown，When action completes，Then document URL 仍公告，tool result 为成功并返回 `owner_transferred:false` 与准确 outcome。 |
| S05.1-AT-03 | Given owner identity 缺失、空或 mixed-actor Batch，When document tool call，Then action fail closed、创建与 transfer 调用次数均为零。 |
| S05.1-AT-04 | Given tool call 同一 `(app,thread,turn,call)` 重放，When first call 已完成，Then result replay 且 create/transfer 外部调用各至多一次。 |
| S05.1-AT-05 | Given fake Sender records request/body/result，When transfer succeeds，Then endpoint、query、document type、notification/remove-old-owner flags 和 openid body 全部匹配；外部 API error 不泄漏给 tool result 或日志。 |
| S05.1-AT-06 | Given current bot process + test Feishu App，When a p2p/group sender creates one test document，Then the document link is visible, target owner is the exact sender, and a transfer failure (if induced) still leaves the URL usable. |
