## 2026-07-14 Delivered 审计发现的 Prompt 入队竞态

独立审查发现 Prompt dispatcher 过去在 `Worker.Accept` 后才把 run 从 `claimed` 写为 `queued`；Worker 若立即开始，会按 token 尝试 `queued → running` 而被拒绝，形成与已修复 Script 相同的偶发 `failed_run_claim`。现在 dispatcher 先原子写 `claimed → queued`，再调用 `Accept`；若 Accept 失败，仍以相同 token 条件收尾为 `failed_enqueue`。`TestPromptDispatcherQueuesRunBeforeImmediateWorkerStart` 以 sqlmock 模拟 Worker 在 Accept 内立即开始，先验证旧顺序失败，再验证 `queued → running` 顺序通过。该整改尚需与 v4 catalog 一起完整门禁、重启和真实 v4 `list_own → update` 验收后，才能标记 Delivered。

为验证既有 Info 诊断不会重新泄露本机 command/Prompt，已补 `TestInvalidSchedulePayloadLogContainsFieldNamesButNotUserValues`：无效 update 日志必须含稳定 event 和参数字段名，但不得含 command 或 Prompt 字符串。它通过后，日志脱敏的 S06 专属覆盖范围包括无效工具 payload、Script 输出 metadata 与飞书 SDK 调用。
