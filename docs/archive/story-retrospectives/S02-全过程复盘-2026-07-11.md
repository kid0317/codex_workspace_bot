# S02 全过程复盘：Worker 队列与流式卡片

> **Story**：S02  
> **状态**：Delivered  
> **日期**：2026-07-11

## 1. 交付结果

S02 交付了按 App 隔离的内存 Worker：group 使用 `chat_id`、p2p 使用 `sender_open_id`；同 key FIFO 将 active Batch 期间到达的消息合并为下一 Batch。work mode 创建并 PATCH 同一张飞书 interactive 卡片，5 秒后回显未来 App Server 参数；companion mode 发送一次 plain-text 参数结果。

真实 p2p 验收中，`batch-2` 将 5 条消息合并为同一请求，5 条 MySQL Message 均为 `succeeded`、共用同一 card message ID，用户确认同卡参数更新成功。最终进程健康，两个 receiver 均 connected；`go vet ./...`、`go test ./...`、`go test -race ./...` 通过。

## 2. 时间线与证据

| 阶段 | 事实与证据 |
|---|---|
| 设计 | 先写 S02 Story，再进行独立技术评审；将 FIFO、p2p/group key、Batch 卡片和 90 分钟状态机回写到 HLD。 |
| TDD | 先建立 Worker Batch、Router key、状态转移、Idle 回收、timeout、companion 的失败测试，再实现最小代码。 |
| 首次真实验证 | 初次消息在新进程启动前到达旧进程，MySQL 留在 `received`；该输入不被用作新版本验收。 |
| 外部协议故障 | 新版本创建 interactive 卡片成功，但最终内容未更新；DB 为 `worker_process_failed`。SDK 证据表明 PUT `Message.Update` 只支持 text/post，卡片必须 PATCH。 |
| 修复与 L4 | 改为 `Message.Patch`，真实 p2p Batch-2 成功；`assistant_content` 的参数 JSON 与用户卡片一致，5 条 Message 共用 card ID。 |
| 实现复审 | 独立评审两轮发现 timeout 成功误记、fallback 状态遗漏、Worker goroutine 回收、companion 缺失；修复后 blocker-only 复审通过。 |
| 交付审计 | Story DoD、Story List、README、HLD、评审汇总和当前运行态同步。 |

## 3. 问题、根因与分类

| 问题 | 根因 | 分类 | 最小永久改进 |
|---|---|---|---|
| 用旧进程收到的消息判断新版本失败 | 重启前后没有以启动时间和新 trace 划分验收输入。 | 缺 SOP / 缺运行门禁 | SOP 要求记录新进程时间；只有其后新 trace 可作验收证据。 |
| 卡片停在“正在处理” | 使用 PUT `Message.Update` 更新 interactive card；SDK 契约限制该接口仅适合 text/post。 | 缺外部协议知识 / 缺测试 | 采用 PATCH；为 card update 添加精确日志，并要求真实 card PATCH L4。 |
| timeout/回收一度不满足设计 | 初版只给 processor context deadline，未把 Worker stop、grace、pending cleanup、goroutine 退出作为状态机的一部分。 | 缺测试 / 缺实现规则 | 以 `Idle/CreatingCard/InProcess/Stopping/Stopped` 驱动 stop channel，加入 work/companion timeout tests。 |
| card failure fallback 留在 received | fallback 前未做条件 `received -> processing`。 | 缺状态机测试 | fallback 先 MarkProcessing，再 Complete；独立评审把 MySQL 终态列为 blocker。 |
| 过早标记 Delivered | 初次交付同步未执行强制复盘/SOP 迭代。 | 缺 SOP 执行门禁 | 本复盘补齐并在 SOP 中新增 S02 不可违反规则。 |

## 4. 残留风险与负责人

| 风险 | 当前边界 | 后续责任 |
|---|---|---|
| processor 完全忽略 cancel | Worker 在 grace 后退出，但该外部 goroutine 不能被 Go 强杀。 | 真实 App Server Story：必须保证 interrupt/turn finalizer 的外部终态。 |
| Batch 生命周期 DB 更新 | 当前为条件逐条更新；数据库异常已会暴露，但不是跨行事务。 | 可靠性/持久化 Story：批量原子更新或补偿策略。 |
| 参数回显 | 仅本机验收，群内可能显示同 Batch query。 | App Server Story：改为真实用户可见输出，默认不展示调试参数。 |
