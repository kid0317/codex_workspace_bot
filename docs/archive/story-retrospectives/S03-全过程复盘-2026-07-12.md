# S03 全过程复盘：真实 Codex App Server 流式调试接入

> 完成日期：2026-07-12  
> 交付结论：Delivered

## 1. 目标与实际交付

S03 将 S02 的模拟参数回显替换为 bot 自有的 `codex app-server --stdio` child：初始化后以共享、并发安全的 JSON-RPC client 服务多个 channel；每个 Batch 复用或创建 ChatGroup Thread，发送真实 Turn，并在个人本地 debug 模式保留 server→client 的 raw、event、outcome 三层证据。

交付时保留的产品边界：个人本地 `all` ingress；不实现 Allow list、命令、审批、附件、Langfuse 或流式内容回吐。飞书只得到固定安全终态，完整原始事件只写本机 debug 文件。

## 3. 这次真正踩到的问题

| 问题 | 根因分类 | 修复与预防 |
|---|---|---|
| raw 完整但索引不能按 Item 查询 | 缺自动门禁 | event 固定写入 nullable 路由字段，支持 direct/nested `item.id`，并增加 observed-shape 测试和新 L4 字段检查。 |
| outcome 正常路径无法区分“无错误”和“无字段” | 缺数据契约门禁 | 每条 outcome 始终写入 `error`，正常值为 `null`。 |
| `duration_ms` 首先为空，修复后仍错误包含 Thread 处理时间 | 缺知识与测试边界 | 时长由 App Server adapter 从接受 `turn/start` 后计到终态；Worker 只持久化 adapter 返回值；可控 clock 测试隔离 Thread 延迟。 |
| 仅有旧 L4 不能证明修复 | 缺运行门禁 | 重启新二进制后发送新消息，逐项验证数据库、三份日志、消息 ID 和进程健康。 |

## 4. 残余风险与后续边界

- debug JSONL 已按用户要求恢复为 info；若后续展示 Story 需要新的真实 payload，需显式开启 debug 并再次执行新进程 L4。
- 本 Story 只验证固定终态卡片；agent delta 的节流、正文展示、工具轨迹和审批仍属于后续 Story。
- 通用 `-32001` server-request 分支、超时/EOF/CAS 冲突由 fake/race 测试覆盖；本次真实 provider 样本未触发这些负向事件。

已将两条可复用规则补入 [Story 从设计到 Delivered](../sop/story-design-to-delivery.md)：协议指标必须在权威边界计时；真实样本暴露索引问题后，必须用新进程、新 trace 检查固定字段与跨文件 join，不能只依赖旧日志或单元测试。
