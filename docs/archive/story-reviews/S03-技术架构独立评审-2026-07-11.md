## 重要项

- `turn/start` response 前的 notification 需要先按 `(threadID, attempt generation)` 注册 collector，再由 `turn/started` 绑定 `(threadID, turnID)`；必须测试迟到 completed、EOF 后旧事件、cancel/completed 竞争。
- `/readyz` 当前只回 receiver snapshot、且 receiver 之前已写 `server_ready`（[main:75](../../../cmd/server/main.go:75)、[main:106](../../../cmd/server/main.go:106)）。需使 initialize 成功成为 ready 前置，连接失效降级且不启动/停止 receiver 可验证。
- 现有 Worker 日志含原 `channel_key`（[manager:305](../../../internal/worker/manager.go:305)），日志目录为 0755（[logging:72](../../../internal/logging/manager.go:72)）。redactor 应在 observer/slog 边界使用 HMAC/salt，诊断目录 owner-only，并对正文、token、Authorization、ID、workspace、stack 做负向扫描。
- `workspace_dir` 当前只验证存在，不验证绝对路径；在 app import 与 server boot 都须强制 `filepath.IsAbs`。

## 必须新增验收

1. 未授权 p2p/group：无 Message、无 Worker、无 `thread/*`/`turn/*` RPC。
2. daemon/proxy 的 absent、version error、initialize failure、EOF、恢复、ready/receiver 状态矩阵。
3. 500s total、90s idle、10s grace、shutdown/EOF、late completed 的唯一失败终态。
4. Thread CAS 全矩阵与跨 Worker/`/new` 竞争。
5. 所有 server request 与未知 request 的 protocol-correct response/error。
6. 多 channel 交错通知、response 前通知和 close 后 late event 的 race/pending 清理。
7. 新进程的真实 daemon/proxy、MySQL、Feishu L3/L4，第二条输入验证 resume，证据仅保存 hash。
