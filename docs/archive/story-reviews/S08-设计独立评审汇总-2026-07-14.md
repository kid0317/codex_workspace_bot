# S08 设计独立评审汇总

> 评审对象：[S08：Langfuse 全链路 Trace 可观测性](../../story/S08-Langfuse全链路Trace可观测性-设计.md)
> 评审日期：2026-07-14
> 角色：Codex App Server 运行时与并发、Langfuse/OTel 数据模型、质量/隐私与交付
> 结论：**拒绝通过；必须整改后重新独立评审。**

## 阻塞项与整改决定

| ID | 三方证据 | 整改决定 |
|---|---|---|
| B1 | 一个 `worker.Batch` 的多条 `Message` 只发一次 `turn/start`，不能把同一个 Item/工具树作为多个完整 Trace | 改为一个 Batch/Turn 一个 canonical execution Trace，使用首条 message 的既有 `trace_id`；非首条 message 只作 HMAC source correlation，不复制树。 |
| B2 | full-content 与 AGENTS/HLD 的 metadata-only 契约冲突；Goal/approval/doc read/attachment 等特殊内容未逐类规定 | 写明这是用户授权的新自托管 Project 受控例外；默认仍 metadata-only；实施须同步 AGENTS/HLD；加入 allow/redact/drop 矩阵，S07 Goal 与审批/附件限制不可绕过。 |
| B3 | 只列 command/file/dynamic tool，遗漏 MCP/webSearch/未知 Item；动态 `item/tool/call` 的 handler result 和 response write 没有事件出口 | 使用通用 Item 投影；新增 tool lifecycle observer，覆盖 call、handler result、response write；未知 Item 不静默丢弃。 |
| B4 | App Server protocol terminal 与 Worker/Feishu/DB request terminal 混为一个 first-wins 终态 | 明确 `codex.turn` 和 root request Trace 两层终态、各自 owner/关闭顺序/late-event 策略。 |
| B5 | 顶层可筛选字段没有精确 OTLP 属性契约；OTLP 原生 type 不应假设 `agent/tool` | 固定 `langfuse.trace.*` / `langfuse.observation.*` 编码表；loop/tool 先发 `span + semantic_kind`；P0 read-back 验证。 |
| B6 | scheduled prompt Trace ID 未持久化，script scheduled run 不在范围定义内 | migration 增加 `scheduled_task_runs.trace_id`，claim 时稳定生成；script run 建无 Codex 的 `scheduled.script` Trace。 |

## 同轮必须吸收的重要项

- OTel 不跨进程重建/补发已关闭 Trace；同一 process 的 exporter retry 复用同一 SpanContext，协议 event 以 generation+seq 去重。
- Redactor 定义输入/深度/数组/聚合上限及 fail-closed；fuzz 覆盖跨 delta secret、URL、JSON、binary 与所有出口。
- 真实验收补实例版本（OTLP 要求 Langfuse >= 3.22.0）、Project access/retention/key revoke、队列/flush/panic 不阻塞业务。

第一轮三个 reviewer 均未修改实现或 Story；本报告只记录可执行的整改来源与决定。

## 用户指定明文策略与 Usage 补充后的复审

> 变更：用户明确要求个人自用的新自托管 Langfuse Project 写入全部业务原文及真实业务 ID；并要求记录每个 Agent loop 与整个会话的 input/output/cached/reasoning/total token usage。
> 结论：**通过，无 blocker；本节决议覆盖本报告中此前关于 HMAC、metadata-only、业务 Redactor/Classifier 与 S07 不进 Langfuse 的旧结论。**

运行凭据仍不是业务数据：Langfuse/飞书 Key、`Authorization`、Cookie、access token、环境 secret 和数据库密码仍不得进入任何 Trace、日志或仓库。

| 角色 | 发现的 blocker | 整改与最终结论 |
|---|---|---|
| Runtime/数据契约 | loop 仅写最后一个 snapshot delta 会漏算；Thread snapshot 若用于 session total 会与 Turn usage 双算 | `loop_usage_accumulator` 按 `(generation,seq)` 去重累计，loop close 才写 usage；session ledger 只接受首次 `(trace_id,turn_id)` 的 `turn/completed.usage`，缺失 completed usage 只标记不完整。复审通过。 |
| Langfuse/OTel | `usage_details` 若直接写包含 cache/reasoning 的 input/output 会重复计数 | 原始 counter 明文保留；仅在算术校验成立时转为互斥 `input`、`input_cached_tokens`、`output`、`output_reasoning_tokens`、`total` bucket。复审通过。 |
| 明文范围与验收 | 单 Trace 64MiB 误写为总上限；MCP/remote-control 高峰 payload 可能只留计数 | 64MiB 改为单 exporter batch，上述内容跨 batch 分片并在 P0/AT/LI 验证可重组；任何含业务或未知 payload 的事件完整写入 generic/overflow。复审通过。 |

本轮复审不把真实 Project 写入、P0 read-back 或 S08-LI-01 误认为已经完成；它们仍是实施后的外部验收门。
