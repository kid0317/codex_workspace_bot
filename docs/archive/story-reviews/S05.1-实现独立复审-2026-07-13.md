# S05.1 实现独立复审（2026-07-13）

## 初审

范围：`router → worker ActorPrincipal → cmd/server Route → feishuaction → feishu Drive`，以及 Owner 转移的安全、幂等、日志和真实验证边界。

| 级别 | 发现 | 处置 |
|---|---|---|
| Blocker | 先前的创建/写入/转移/公告共用 20 秒 context；若 Drive 转移耗尽 deadline，后续 URL 公告继承已取消 context，违反“best-effort 不阻断链接”。 | 修复：转移使用独立 5 秒 context，公告使用独立 15 秒 context，均从 `context.WithoutCancel(operationCtx)` 派生；增加已取消 operation context 的回归测试。 |
| Important | SDK request 的私有 query/path 不能由普通 fake 直接读取。 | 缓解：使用 pinned Lark SDK 的 generated `TransferOwner` builder；单测断言 `docx/openid/member_id` 输入和返回分类；修复后真实 p2p/group L4 均返回 `transferred`。 |
| Important | L4 直接调用 Sender，不是 WebSocket ingress 到动态工具的完整 E2E。 | 保留分层边界：Router/Worker/Route 的 group/mixed actor 测试覆盖身份链，L4 覆盖真实 Drive + p2p/group delivery；不把它描述为 App Server 模型选择工具的证明。 |

## Blocker-only 复审

结论：**通过**。

- 转移的独立 5 秒预算与公告的独立 15 秒预算已隔离；转移超时不会耗尽公告预算。
- `TestDocumentPostCreateContextSurvivesOperationCancellation` 证明写入 operation context 已取消时 post-create context 仍可用。
- 修复后的新进程完成第二轮真实 p2p 与 group L4，两个结果均为 `owner_transferred=true` / `transferred`。
- 未发现 Owner 从回复目标、群 chat ID 或模型参数获取的路径；missing/mixed actor 仍 fail closed。
