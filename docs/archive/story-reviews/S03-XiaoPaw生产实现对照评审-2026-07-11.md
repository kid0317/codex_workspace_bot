## 不可照搬的差异

1. XiaoPaw 私有 sandbox WebSocket 的顺序 `_wait_response` 不能满足 S03 单连接、多 Worker 的 response correlation、reader/writer 串行与 thread/turn 分派。
2. XiaoPaw adapter 只消费少数 notification：无 method 的 response 忽略，server request 无回包，未知 notification 不记录；这直接违反 S03 的四类 JSON-RPC 分类和未知事件观察目标。
3. XiaoPaw 的 resume response 未显式 fallback start；S03 必须 CAS 替换 Thread 并记录 `resume_fallback_started_new_thread`。
4. XiaoPaw 对任意 `turn/completed` 更宽松；S03 必须按 status 将 failed/interrupted 归为失败。
5. XiaoPaw 有意上屏 delta/reasoning/tool/final answer，且部分 debug 带原始标识；S03 本期必须只上固定终态，日志只存 hash、结构和长度/hash。

## 对 S03 的整改建议

### 阻塞

- 不得复用 `_run_codex_turn` 或其 WebSocket client。独立实现 `codexapp.Client`：唯一 reader、唯一 writer、`pending[id]` 与 `turnCollector[threadID/turnID]`，四类消息互斥分类。
- 先裁决 daemon/proxy 模型并同步 HLD。XiaoPaw 的 sandbox supervisor 不能证明共享 daemon 可被本机 bot 安全 restart。
- 对 resume failure、`turn.completed.status != completed`、EOF、timeout、server request 都收敛为一次 failed，绝不自动重放。
- 实现 S03 专用 redactor；不采用 XiaoPaw 的原始 SSE/debug 内容策略。

### 重要

- 迁移“HTTP alive 不等于 App Server ready”的经验：S03 `/readyz` 必须在 daemon/proxy + initialize 成功后才 ready，并在 L4 同查 DB、同卡 PATCH、脱敏事件链与第二轮 resume。
- 迁移“流断无 completed 必失败”的经验，但不引入 FC、NAS、Redis、session 表或 responses proxy。
- XiaoPaw 的 active turn interrupt 只带 thread ID；S03 必须用当前 schema 实测 interrupt params，后续 Command Story 再交付 `/cancel` UX。
- XiaoPaw happy-path SSE 测试不够；S03 必须覆盖 response 前 notification、交错 Worker、server request、EOF、timeout、resume fallback、card fallback 与 race。

### Future

FC Session、NAS 三态、Redis lease、计费、responses proxy 和 XiaoPaw `process_delta` 卡片体验均不属于 S03。后续流式卡片 Story 可参考其展示体验，但必须重新定义可展示事件、内容安全和节流。
