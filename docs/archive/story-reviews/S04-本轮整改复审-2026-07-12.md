## 阻塞项

### B1：full entity update 一次失败后永久降为 PATCH

**证据链：**

1. `internal/feishu/feishu.go:157-171` 的 `UpdateBatchCardZones` 每次本应先调用 `updateCardKitEntity`，失败后仅对当前 message 做 `patchCard`。
2. 但 `internal/feishu/feishu.go:200-207` 在 `Card.Update` 返回 transport/API 失败时调用 `s.dropCardSession(messageID)`。
3. `internal/feishu/feishu.go:180-186` 随后的同一 message 更新找不到 session 后返回 `cardkit session unavailable`；外层再次走 PATCH。因为 session 已删除，后续不可能再发出该实体的 `Card.Update`。
4. `cardKitAvailable()` 恒为 `true`、`disableCardKit()` 只记日志，不能修复被删除的 per-message session。现有 `TestCardKitFailureDoesNotDisableFutureFullEntityUpdates` 只调用这个空实现，未模拟 `Card.Update failed -> dropCardSession -> next update`，因此没有覆盖实际违约路径。

这与 `AGENTS.md`、`docs/sop/story-design-to-delivery.md` §10、S04 AT-06、S04 §8 失败处理、以及 HLD 第 371 行的正式契约相冲突：PATCH 只能作为一次更新的降级，不能永久接管后续卡片。

**解除条件：** 保留可再次 full-update 的同一实体会话（或提供等价的可恢复重建/重试机制），并新增 fake SDK/transport 测试，按同一 `message_id` 验证“第 N 次 Card.Update 失败 -> 本次 PATCH 成功 -> 第 N+1 次仍发出 Card.Update”。修复后重跑本报告中的门禁并重新 blocker-only 复审。
