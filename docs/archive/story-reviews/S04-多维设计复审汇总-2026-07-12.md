## 2. 共同认可的设计基础

1. work 与 companion 的输出模式分流是正确的：work 保留双区卡；companion 终态前零可见输出、只在成功 Terminal 后发送 final。
2. 仅投影已绑定 Turn 的 allowlisted `item/completed.agentMessage`，并将 `commentary`/`final_answer` 分区，是比 XiaoPaw 的 delta/process 上屏更适合本产品的收口。
3. CardKit 的 stable UUID、operation ledger、SendUnconfirmed 和 L3/L3b/L4 实测门是合理的；不应以当前 PATCH 基线替代 CardKit 主路径证据。
4. companion 对旧 CC Bot 的精确 `[[SEND]]`、fallback、打字节奏、429 单次重试、普通错误继续和取消语义已基本对齐；兼容 Lexer 是受控增强，而非错误迁移。

## 3. 必须先回写的 P1 设计建议

| ID | 建议 | 由哪些评审支持 | 建议落点 |

| P1-3 | 为“飞书请求结果不确定”和“DB 收尾失败”定义保守语义：未知 SendText 不自动重发当前段；每段 trace 记录 `sent|failed|unknown|cancelled`；DB finalize failure 有稳定错误码/告警，不以重发消息补数据库。 | CC P1、测试 T1/T2/T5、XiaoPaw XP-S04-05 | S04 companion sender、delivery summary、normal structured trace、AT/L2。 |

## 4. 需要用户确认的三个取舍

| 决策 | 方案 | 建议 | 影响 |
|---|---|---|---|
| D1：successful Terminal 后分段发送中进程重启 | A. 不自动重发，标记交付已中止；B. 增加 durable segment ledger/outbox，以 cursor 恢复未确认段。 | **已裁定 A**：不自动重发；遗留 processing 标记为 `companion_delivery_abandoned`。 | 可能少送余段但不会重复；不引入 schema 或恢复语义。 |
| D2：companion 分段的容量预算 | A. 有上限，超过后合并为一条完整文本/附带确定性提示；B. 不设上限，保持所有陪伴段。 | **已裁定 B**：不设总分段/总时长/总字节限制。 | 同 channel 可能长期被 delivery 占有；通过 `/cancel`、`/new`、Worker stop 中断，不做截断/合并。 |
| D3：旧 CC persona 输出过滤效果 | A. 明确不迁移 `FINAL_REPLY.md`/Claude hook；B. 后续开 Codex-native output-policy Story 保留其产品效果。 | **已裁定 B（后续 Story）**：S04 不复制 Claude 文件 hook；后续以 Codex-native policy 满足。 | S04 不承诺旧 hook 的过滤效果；该能力另行产品化与评测。 |

**已纳入 S04 设计修订**：P1-1 至 P1-6，以及 P1-4 的“展示背压即确定性失败”策略；不引入 spill queue。后续三轮 blocker-only 复审进一步纳入 DeliverySlot/BeginDelivery、post-bind count+byte reservation、持久 batch/stage 与 `FailCompanionDelivery`；第三轮已 PASS。

## 5. P2 设计与测试完善项

1. 明确 `streaming.companion_segment_delay_ms` 只覆盖旧 `BaseDelay=400ms`，其余 SegmentOptions 沿用固定默认；注入 fake clock/RNG，禁止基于真实 sleep 的脆弱测试。
2. 固定 normal structured delivery trace schema 与 sink：至少 `batch_id, source_trace_ids, thread_id, turn_id, segment_index, text_sha256, result, message_id|null, retry_count, at`；不记原文。定义 writer 失败的 error code。
3. 增加 Lexer + Segmenter 的 golden/fuzz corpus：NBSP/零宽/emoji/CJK、quoted/list、backtick/tilde fence、不配对 wrapper、反斜杠 1/2/3、internal token collision；每例同时断言 `storage_text`、`segmenter_input`、出站段和 token 不泄漏。
4. L4 不让模型随机 marker 变体承担全部验证：L1/L2 用固定 fixture 覆盖 grammar；L4 只验证真实 ingress→无占位→Terminal 后多消息及 MySQL/trace 关联。至少保留成功多段与失败/empty 两条新 trace。
5. 真实 CardKit 能力仍以 L3/L3b/L4 为硬门：entity send/retry、element update、settings close、entity-backed message PATCH 分别实测；PATCH 降级成功不能宣称 CardKit 主路径成功。

## 6. 建议修订顺序

1. 已记录 D1–D3，并已回写 P1-1 至 P1-6 与对应 AT/HLD 契约。
2. 发起 blocker-only 设计复审；通过后恢复“Ready 可开始实现”的结论。

4. 实施后通过 race/transaction/fixture gate，再做 CardKit L3/L3b 与 work/companion L4。
