## 2. 必须在实现前关闭

| 优先级 | 共识问题 | 汇总决议 |
|---|---|---|
| Blocking | 每 App 的 AllowedChats 没有模型或前置校验 | 增加 `app_allowed_chats`，默认 allowlist；Router 在任何业务落库、投递或回复前校验。`appctl` 管理规则；未授权不创建 ChatGroup/Message、不回复。 |
| Blocking | 同 `channel_key` 串行化被后置，且 ACK 会被同步发送阻塞 | Story 1 实现最小有界 channel dispatcher：回调完成授权+幂等落库即 ACK，dispatcher 串行发送和收尾。固定 20 active workers、64 queue depth；满载创建 `rejected` 并给确定性回复，绝不静默丢失。 |
| Blocking | Message 归属可跨 App | 移除 `messages.app_id`，以 `chat_group_id` 为唯一归属并通过 join 查 App；幂等唯一键使用 `(app_id, feishu_event_id)` / `(app_id, feishu_user_message_id)`，`trace_id` 保持全局唯一。 |

## 3. 实现前应纳入设计的 Major

1. **迁移执行器**：`schema_migrations`、checksum、MySQL advisory lock、只向前、失败 fail-fast；覆盖重复、并发和中断诊断。
2. **生命周期**：定义 receiver/dispatcher 的启动、`degraded`、退避重连、关闭和 drain；正常关闭将未完成轮次写为 `failed/shutdown_interrupted`。MySQL/迁移失败 fail-fast；单 App 的飞书连接失败隔离为 degraded，readiness 按“至少一个 enabled receiver 可用”判断。
3. **App 管理语义**：一期明确 `appctl enable/disable` 需重启生效；有历史的 App 只能 disable，物理 delete 仅无依赖；Secret 仅 stdin、无回显交互或受限文件输入，禁止 argv。
4. **飞书事件防御**：校验 `header.app_id == receiver.feishu_app_id` 与非空 `header.event_id`；固化 p2p/group/topic_group fixture，覆盖真实路由 ID 与重复事件。
5. **App Server future mapper**：`reasoning_effort` 仅发给 `turn/start.effort`；按各 API 正确映射 `sandbox_mode`，不得将字符串直接填入 Turn 的对象 `sandboxPolicy`。
6. **脱敏与状态**：固定回复不显示 raw chat_id/open_id；状态机以条件更新限制合法转换；日志和 Langfuse metadata 不含正文、Secret 或飞书原始标识。
7. **配置和健康**：Story 1 模板只保留实际生效的 logging/database/worker/shutdown/health；未来 Codex/Langfuse 配置另列。定义本地 `/healthz` 和 `/readyz`，并写明 DB、迁移、receiver 状态条件。

## 4. 保持不变的设计决策

- 保持 `apps → chat_groups → messages`；不恢复单独 Session 表。
- 保持一轮一条 Message 与生成即固定的 UUID `trace_id`。
- 保持 App 配置在 DB、进程配置在 YAML/环境变量；飞书 App Secret 按个人使用要求在 DB 明文，但全链路不回显、不记录。
- 保持一期只支持 `text + p2p/group` 固定回复；`topic_group`、附件、卡片、App Server、Langfuse 写入均不在一期实现。
- MySQL 保持 host bind mount、localhost 发布和 `restart: unless-stopped`；固定镜像到 patch tag/digest，实际实现时验证 Docker systemd 已 enabled。

## 5. 新增验收要求

- 未授权 p2p/group：无业务记录、无回复。
- 同 channel 两条消息严格按入站次序发送；不同 channel 可并行；队列/worker 满有一条可追踪拒绝。
- 慢 sender 不阻塞飞书 ACK；并发重复 event 只产生一条出站消息。
- event header App ID 不匹配、event ID 为空、`topic_group`、非 text 均无业务副作用。
- App 有历史时 delete 被拒绝；disable 后重启不再连接；Secret 不出现在 argv、list、日志或错误。
- 空库/重复/并发/失败迁移，SIGTERM drain、遗留 processing 收敛，WebSocket reconnect/receiver degraded 均有测试或明确 smoke 证据。
- schema mapper 对 Thread/Turn 的 approval、sandbox 和 effort 做单测。
