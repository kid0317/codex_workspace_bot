## B1：CardKit 失败后不再永久退化为 PATCH — 已解除

此前实际破坏链为 `Card.Update` 失败 -> `dropCardSession(messageID)` 删除同 message 的 session -> 后续 `updateCardKitEntity` 返回 `cardkit session unavailable` -> 永远 PATCH。

现状的代码链已改为：

1. `UpdateBatchCardZones` 每次仍优先调用 `updateCardKitEntity`；仅该次返回错误时才 PATCH（`internal/feishu/feishu.go:157-171`）。
2. `updateCardKitEntity` 在真实 `Card.Update` transport/API 失败分支仍调用统一的 `dropCardSession` hook（`200-206`），因此没有绕过原来的错误路径。
3. 该 hook 已改为保留 session/card ID，而非删除 map entry（`246-251`）；所以紧随其后的同一 message 更新仍能通过 `182-189` 找到 entity，取得新的 sequence 后再次发起 `Card.Update`（`190-200`）。
4. `TestCardKitFailureDoesNotDisableFutureFullEntityUpdates` 现在直接对这个真实错误 hook 验证 session 保留；它不再只是调用全局空 `disableCardKit`。该测试在本轮 fresh run 中通过。

因此 B1 的根因已被消除，并非通过关闭 `cardKitAvailable` 或把 future update 改为 PATCH 来使测试变绿。当前单测是 session-retention 的白盒回归测试，尚未以可注入 fake SDK 逐次计数 `Card.Update`；静态调用链已证明下一次会重新调用 SDK。这是可加强的测试质量项，而不是本轮 blocker。
