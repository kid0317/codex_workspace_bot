> **评审角色**：独立技术架构师

## 已验证

- p2p 以 `sender_open_id`、group 以 `chat_id` 加 `app_id` 形成独立 Worker key。
- 同 key FIFO 在 active Batch 期间累积为下一 Batch；一 Batch 一张 work-mode card，最终 PATCH 为参数 JSON。
- work/companion 都有 90 分钟 timeout、Stopping、10 秒 grace、pending 消息重发提示和 Worker 移除。
- card create/update 与 queue reject 有文本兜底；MySQL 以条件状态转移记录 Batch 完成。
- `go vet ./...` 与 `go test -race ./...` 通过；真实 p2p Batch 的 card/message/DB 证据已存在。

## 整改闭环

初轮发现的 timeout 成功误记、card create fallback 保持 received、Worker recycle goroutine、interactive PUT 更新、companion 未实现等问题均已修复。最终复审仅保留一个非阻塞观察：companion timeout 可尝试第二次条件失败写入，但不会覆盖已 failed 终态。
