## 1. 已核对的需求

- Agent 能获取、添加、修改自己在当前 App/频道/用户归属下的 CronTab 定时任务。
- MySQL 保存任务归属、规则、类型、静默设置；Prompt 到点模拟原频道、进入 Worker FIFO；Script 到点执行 Shell 脚本。
- 静默不自动推结果；非静默 Prompt 返回 App Server 结果卡，非静默 Script 返回控制台结果卡。

## 3. Important 已采纳项

- `ClaimDue` 必须 `SELECT ... FOR UPDATE` 后重验 enabled/route/version/slot，tool call claim、task mutation 和加密 replay result 同 transaction；in-flight claim 有恢复规则。
- state、error code、delivery intent 分列；card/text 外呼采用 `pending → in_flight → sent|rejected|unknown|suppressed`，unknown 不重发，只有明确 rejected 才允许一次 fallback。
- 固定 quota（owner 100、App 1,000）、Prompt tick budget 20、Script concurrency 2；饱和时写 terminal `failed_capacity`，不积压无界任务。
- `misfire_grace_seconds` 最低 1 秒，归属 `schedule`；`scripts` 只包含运行器设置。HLD/README 已同步为 S06 定时任务，移除旧命令 Story 归属。
- due claim 重验 App enabled 与 ChatGroup route；App disable、bot 离群/频道撤销关闭 route，禁止 silent Script 继续执行。
- 首次 blocker-only 额外发现：run 表不能用单个 delivery 字段表达 primary card、fallback text 与 unknown。第二轮新增 `scheduled_task_deliveries` outbox；每次发送独立 intent，S06 不发送执行中卡。

## 4. 本轮不采纳/后续项

- 不加入 delete、时区选择、秒级 Cron、catch-up replay、分布式 leader、任意 Shell command 或跨频道通知；这些均不属于用户本期范围。
- 旧“飞书斜杠命令与时间上下文”设计保留为 Superseded 历史文档，不作为本 Story 的评审证据或现行编号。
