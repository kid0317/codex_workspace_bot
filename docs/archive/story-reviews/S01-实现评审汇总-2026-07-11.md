# S01 实现后多角色评审汇总

> 评审角色：AI 技术架构师、质量工程师、产品架构师
>
> 结论：真实 p2p/group 文本收发与持久化已验证，但 **S01 不可标记 Delivered**。

## 已确认能力

- `health-assistant` 已真实连接飞书；p2p 与 group 各有成功 Message、出站 ID、Trace ID、完成时间和耗时。
- ChatGroup 按 `(app_id, chat_type, chat_id)` 建模；当前真实 p2p/group 分别落库。
- MySQL Docker 重启后的数据仍存在；`/healthz` 可用。
- 普通日志已写入 `logs/server.log`，WF current 文件已创建。

## 必须在交付前处理

1. **App 管理入口**：补齐 `appctl create/list/update/enable/disable/delete`，list 脱敏；或由产品明确缩小 S01 范围并修改设计。
2. **迁移演进**：实现带 `schema_migrations` 的前向版本化 migration runner。
3. **入站原子性**：ChatGroup upsert、Message 创建和 duplicate 判定必须在同一短事务；飞书发送在事务外。
4. **日志可靠性与容量边界**：修复切分与并发写入的锁关系、错误可见性和半失败恢复；新增 retention days（可选总量上限），避免长期磁盘耗尽。

- README、Story 状态、DoD 和已完成真实联调证据同步。
