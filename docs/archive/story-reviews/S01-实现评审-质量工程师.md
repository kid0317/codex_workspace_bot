# S01 实现评审：质量工程师

> 日期：2026-07-11｜已检查 `go vet ./...`、`go test ./...`、`go test -race ./...`；三者通过，但不覆盖关键运行失效路径。

## 阻塞项

| 问题 | 证据 | 风险与建议 |
|---|---|---|
| App CRUD 缺失 | `cmd/appctl/main.go` 只接受 `import-legacy-app` | 无法创建、禁用、更新问题 App。补 create/list/update/enable/disable/delete，list 永不回显 Secret。 |
| 入站持久化非原子 | `internal/storage/messages.go` 先 upsert ChatGroup 再 insert Message | SQL 间失败会留下孤立 ChatGroup，违反设计。增加短事务及真实 MySQL 回滚测试。 |
| 日志轮转存在并发丢失窗口 | Handler 与 `Manager.rotate` 使用无关锁 | 可能写入关闭文件；增加共享锁和并发压力测试。 |

## 重要项

- 轮转半失败后 Manager 无法自恢复；后台错误被吞掉。
- 归档不删除，长期磁盘耗尽；需 retention/容量上限。
- Receiver 没有应用层重连和状态机，`/healthz` 仅检查 MySQL。
- `UpsertApp` 在双唯一键冲突时不更新应用身份；需明确 create 与 update 语义。
- DB/应用层未严格校验 mode、effort、chat type、status 等枚举。
- HTTP 缺少 read/write/idle timeout；DSN 手工拼接不能稳健处理特殊字符密码。
- 缺少 migration 版本表、启动关闭测试、真实 MySQL 约束测试和日志并发切分测试。

## 安全观察

日志文件权限为 `0640`，但日志目录为 `0755`；本机多用户时应收紧目录权限。SDK 仍可能输出 stdout/stderr，需明确由进程管理器接管或定向。
