# S06：飞书斜杠命令与时间上下文

> **状态**：Superseded（2026-07-13；原编号已更正为 [S06：定时任务与 Agent 工具](S06-定时任务与Agent工具-设计.md)；其中 `/goal` 契约由 [S07：Goal 持续执行与终态展示](S07-Goal持续执行与终态展示-设计.md) 取代）  
> **关联概设**：[HLD v4.3](../02-redesign-high-level.md) §2.3、§4、§5.7、§7  
> **依赖**：S01–S04 已 Delivered；已登录的本机 Codex App Server；测试飞书 App 的消息与卡片权限。

## 1. 一句话目标

让飞书用户能在每个独立频道中开始新会话、取消任务、查看 Codex 账户用量、设置长期目标和获得帮助；每条**普通**用户文本还会携带可审计的上海时区 `now` XML 上下文进入 Codex。

## 2. 背景

现有 Router 已在 receipt 去重后直接识别 `/new`、`/cancel`、`/stop`；Worker 已能中断活跃 Turn、等待 companion 交付收尾，`Processor.NewSession` 能归档并清空当前 Thread 指针。但现有 `Manager.Cancel` 只中断活跃 Batch，不会移除同频道 FIFO 中等待的消息，尚不满足“清空所有队列”。普通文本进入 `turn/start` 时也没有用户消息发生时间。

本机 `codex-cli 0.144.1` 生成的 schema 与官方 App Server 文档已确认：

- `turn/interrupt` 用于中断活跃 Turn；
- `account/rateLimits/read` 返回额度窗口的 `usedPercent`、`windowDurationMins` 和 Unix 秒 `resetsAt`；`account/usage/read` 返回 token 活动摘要和可选日用量桶；
- `thread/goal/set {threadId, objective, status?, tokenBudget?}` 是原生长期目标接口。

所以 S06 不解析 CLI 终端输出，也不把目标伪装成普通 Turn；它调用 App Server JSON-RPC 并按飞书产品语义呈现。

**概设影响（已接受并同步）**：S06 已改变 HLD 的命令路由、`/status` 语义、Thread goal 使用范围、命令结果交付以及普通文本时间上下文；本 Story 是实现与验收的细化契约。

## 3. 范围

### 3.1 本期做什么

1. 解析精确的 `/new`、`/cancel`、`/status`、`/goal <目标>`、`/help`；保留既有 `/stop` 为 `/cancel` 兼容别名，但不在帮助中宣传，也不新增其它别名。
2. 每条普通文本进入 `turn/start.input` 前，添加上海时区前缀：`<now timezone="Asia/Shanghai">2026-07-13T16:20:00+08:00</now>`。
3. `/cancel` 与 `/new` 在 receipt 去重后立即进入频道控制面：原子清空等待 FIFO、取消活跃 Turn/companion delivery，权威终态收尾后发送确认卡。
4. `/new` 在取消完成后尽力归档当前 Thread，条件更新清空 `chat_groups.codex_thread_id`；下一条**普通**消息才懒创建新 Thread。
5. `/status` 在 receipt 去重后直接调用 `account/rateLimits/read` 与 `account/usage/read`，返回一张无敏感账户标识的状态卡，显示用量和按上海时区格式化的重置时间。
6. `/goal <目标>` 是频道 FIFO 中的独占工作项：原样传递目标文本到 `thread/goal/set`，绝不加入 `<now>`；目标明文只存活于该内存工作项，绝不写入 MySQL、飞书输出、日志、Langfuse、workflow JSONL 或 debug timeline。
7. `/help` 返回固定静态卡；未知斜杠命令和不合法参数保存 receipt 并返回确定性错误卡，绝不作为普通提示词送入 Codex。
8. 增加 parser、控制屏障、队列清理、Thread 生命周期、时区渲染、账户状态降级与 receipt 幂等测试，并提供真实 App Server/飞书的 L3/L4 smoke。

### 3.2 本期不做什么

- 不实现命令补全、菜单、按钮回调、自然语言别名、权限体系或管理员指令。
- 不复制 Codex TUI 的完整 `/status` 本地配置面板；仅展示 App Server 可授权返回的用量和额度数据。
- 不实现 `/goal` 的读取、暂停、完成、预算和清除子命令。
- 不改变认证、额度兑换、模型/权限配置或跨频道并行策略。
- 不把账户邮箱、token、credit ID、原始 App Server 响应、用户目标正文写入日志、MySQL、Langfuse、workflow JSONL 或 debug timeline。
- 不处理附件、多媒体、富文本命令输入；S05 边界不变。

## 5. 核心设计决策

| 问题 | 结论 | 原因 | 后果 |
|---|---|---|---|
| 第五个命令的拼写 | `/goal <目标>`，不接受 `/go` | 需求的五命令清单写 `goal`，本机协议也有 `thread/goal/set`；未找到 `/go`。 | `/go` 是确定性未知命令；不暗中支持两个拼写。 |
| `/goal` 执行方式 | 进入 Worker，作为独占 `Goal` 工作项，不生成普通 Turn | 它必须与 `/new`、普通 Turn 和 Thread 指针串行，且使用原生目标接口。 | 不附加 `<now>`，目标文本不会混入普通输入。 |
| 无 Thread 或 resume 失败时 `/goal` | 提示“请发送一条普通消息以建立/恢复会话”，不创建 replacement Thread | 项目约定 `/new` 后下一条**非命令**消息才懒创建 Thread；命令不能破坏该边界。 | 不新增 pending-goal，也不在 goal path 调用 `thread/start`。 |
| `/status` 路由 | receipt 去重后直接查询、不进 Worker | 需求明确它直接生效；账户 RPC 不读写 Thread/Turn，client 支持并发关联。 | 它是同频道 FIFO 的显式只读例外，可能与 `/new` 乱序完成，卡片必须显示查询时间。 |
| `/new`、`/cancel` 清队列 | 对线性化点之前已接纳、尚未启动的同频道 Message 条件标记 `cancelled_by_command` 并从 FIFO 移除 | 仅 interrupt 活跃 Turn 不满足需求，且不能留下永远 pending 的记录。 | 不删除历史、不撤回已可见输出、不影响别的 App/频道。 |
| 控制与普通 ingress 竞态 | Worker 独占 `SubmitControl` API 建立 barrier；普通 `Accept` 不得越过已受理的控制命令 | 事件可以交错，不能让新消息进入旧 Thread 或被错误清掉。 | ingress 最多等待 2 秒；超时的普通消息标 `channel_control_in_progress` 并发送固定 text fallback。 |
| 时间来源 | Router 接收时由可注入 Clock 捕获，不取 Worker 延迟处理时间 | FIFO 可能等待很久，模型需要用户实际发送时刻。 | `messages.received_at`（UTC 毫秒）和 Worker `ReceivedAt` 记录同一事实；DB `user_content` 不混入派生 XML。 |
| 时区/XML | 固定 `Asia/Shanghai`、RFC3339 秒精度；每条普通文本前缀 `<now timezone="Asia/Shanghai">…</now>\n` | 明确、可测试，且 Batch 合并后仍保留逐条时间。 | 用户自写 XML 不获得特权。 |
| 命令确认卡 | `CommandResponder.SendStaticCard` 发送无交互静态卡，明确失败时降级一次 plain text；原任务卡仅由 Worker 的权威 Terminal 路径关闭/标终态 | Router 直接篡改 active card 会与 S04 Projection/DeliverySlot 竞争。 | 每次可见尝试有 10 秒 deadline、28 KiB card 预算、message ID/outcome 持久化；unknown 不重复发送。 |
| 共享 App Server 的 start-in-flight cancel | 每个 Batch 从 dequeue 起就有 cancel latch 和 `TerminalArbiter`；取消不得用请求 context 终止共享 client | `turn/start` response 可能尚未返回；现有任意 request error 会关闭 generation，不能让一个频道的 cancel 伤害其它频道。 | response 晚到时绑定 turn ID 后立即 interrupt；仅进程/协议失败可退役 generation。 |
| `/status` 可显示字段 | 显示 bucket 已用百分比、窗口与 `resetsAt`，以及可用 token summary/daily bucket | rate limit 不承诺“剩余 token”。 | 任一接口不可用仍显示另一部分，标“暂不可用”，不显示原始错误。 |

## 6. 主链路与数据/接口契约

### 6.1 命令语法与 receipt 顺序

Router 先无副作用分类，再执行附件 staging、`PersistIncoming` 与 duplicate 检查；任何副作用都在 duplicate=false 后：

```text
trim Unicode outer whitespace
first rune != '/'                         => NormalText
else split first whitespace into token/remainder
lowercase token only

/new, /cancel, /stop, /status, /help     => remainder 必须为空
/goal                                    => remainder trim 后必须非空，保留原 remainder
其它                                      => InvalidCommand
```

不做 quote、shell、XML 或 Markdown 解释。`/goal`、`/new extra`、`/status x` 均不进入普通 Turn。

所有命令仍先创建 receipt；为保证 `/goal` 隐私，新增前向 migration：

```text
messages.received_at              DATETIME(3) NOT NULL       -- Router 时钟的 UTC 事实
messages.command_kind             NULL|new|cancel|status|goal|help|invalid
messages.command_payload_sha256   CHAR(64) NULL              -- 仅 /goal 的参数 digest
messages.command_payload_bytes    INT NULL                   -- 仅 /goal 的 UTF-8 byte 长度
messages.command_effect_state     pending|succeeded|failed
messages.command_reply_outcome    pending|sent|rejected|unknown
```

`/goal` 的 `user_content` 固定写为 `"/goal [redacted]"`，不会写入 objective；其它命令保留其安全、无参数的字面 token。Feishu event ID 仍是唯一 receipt/idempotency 键。objective 明文只保留在 `Goal` 内存 job，完成、失败、进程退出或 10 秒控制 deadline 后立即释放。`codexapp` 的 raw-timeline writer 在 `thread/goal/set` response 和 `thread/goal/*` notification 写盘前用结构化 redactor 将 `goal.objective` 替为 digest/长度标记。

### 6.2 普通文本时间输入

`router.Incoming` 和 `worker.Message` 增加 `ReceivedAt time.Time`。Feishu Normalize/Router 通过注入 Clock 设置它，且同一个 UTC 毫秒写入 `messages.received_at`。Processor 不再直接 `strings.Join(batch.Queries(), "\n")`，而是对每一条普通 Message 生成：

```text
<now timezone="Asia/Shanghai">2026-07-13T16:20:00+08:00</now>
<原始用户文本>
```

再按 FIFO 以换行拼接为一个 `turn/start.input[{type:"text"}]`。用户正文在标签后作为 opaque、byte-preserved text 拼接；`</now>`、嵌套/伪造 `<now>`、CRLF、NUL、控制字符、Unicode whitespace 都不改变服务端标签的含义。附件仍按 S05 typed input 追加；所有命令和无效命令都不经 formatter。

### 6.3 Worker-owned control API、`/cancel` 与 `/new`

```text
Router: PersistIncoming(receipt) → duplicate? stop → Worker.SubmitControl(command) → return ingress

Worker control goroutine (same channel owner):
  → lock: barrier=true; detach queue; ensure active Batch owns activeDone from dequeue
  → storage.FailQueued(atomically, cancelled_by_command)
  → TerminalArbiter.Claim(cancelled), set start-in-flight cancellation latch
  → request turn/interrupt when a turn ID is bound; wait interrupt grace <=10s
  → force local command terminal on grace expiry; wait DeliverySlot.done <=10s
  → Worker normal terminal closes original task card exactly once
  → /new: thread/archive, then CAS clear codex_thread_id
  → record effect outcome, deliver command result once, release barrier
```

`SubmitControl` 是新增 Worker-owned API，不是 Router 顺次调用 `Cancel`/`NewSession`。它在同一 mutex 下决定命令线性化点、detach FIFO 和 active cancellation latch；多个 control command 按受理顺序执行，第二个在第一个完成后按当时状态幂等处理。`activeDone` 和 all-mode `TerminalArbiter` 在 Batch 从队列取出时创建，覆盖 `CreatingCard`、`turn/start` in-flight、work 和 companion；所以 `/new` 不能在 Batch 即将启动 Turn 时提前 archive。

Router 不等待模型、卡片或 archive：它在 receipt 和 `SubmitControl` 被接纳后立即返回，以满足 2 秒入站边界。控制 job 使用独立 background context；普通 ingress 在 barrier 内最多等待 2 秒，超时将该普通 receipt 标 `failed/channel_control_in_progress` 并以一次 text fallback 告知重试。detach 的 DB 条件更新失败时，已分离消息保留在不可执行的 `discarding` 集合并仅重试该 transaction；不重新入队、不启动 Turn。最终失败写 `command_queue_persist_failed` 并释放 barrier。

`/cancel` 不清空 Thread，后续普通消息继续原上下文；`/new` 才清空。无 active Batch/Thread 时仍是幂等成功。archive 失败时不得先清 DB 指针，命令记录 `command_archive_failed`。`/new` 的成功卡为“已开启新对话。下一条普通消息将创建新的 Codex 会话。”

### 6.4 `/status`

`/status` 不用 `turn/start`，不占 FIFO；它是 app-account-scoped 的只读例外，可能在同频道后到的 `/new` 前后乱序完成，故卡片必须显示 `查询时间`。它在初始化完成的 `codexapp.Client` 上并发调用：

```json
{"method":"account/rateLimits/read","params":{}}
{"method":"account/usage/read","params":{}}
```

卡片包含查询时间、`rateLimitsByLimitId` 的每个 bucket（缺失时 fallback `rateLimits`）的显示名、已用百分比、窗口分钟数、按上海时区格式化的 `resetsAt`，以及服务提供时的 lifetime/peak/longest-turn/streak 和今日日 token。null 为“未提供”，单接口错误为“暂不可用”；绝不显示 email、credit ID、token、原始 JSON、stack 或内网错误。

### 6.5 `/goal`

Worker 队列引入普通 `Text` 和独占 `Goal` discriminator；Goal 不同普通文本合并。轮到 `/goal` 时：

1. 读取 `chat_groups.codex_thread_id`；为空只提示先发普通文本。
2. 有 Thread 时以当前 `workspace_dir` 调用 `thread/resume`。
3. `thread/resume` 失败时不调用 `thread/start`，只返回“请发送一条普通消息以恢复会话”；随后的普通消息才可走既有 resume fallback。
4. 仅在 resume 成功后调用 `thread/goal/set`：`{threadId, objective:<原样目标>, status:"active"}`。
5. 成功后只发通用确认卡“长期目标已设置”，不显示 objective 或摘要；日志只写 digest、长度、稳定关联 ID 与 outcome。

目标接口不接受 `cwd`，故 resume 是确认 Thread 已按本 App workspace 加载的必要步骤。它不创建 Turn，也不添加 `<now>`。

### 6.6 `/help`

固定卡片的正文如下，模型不参与生成：

```text
/new          结束当前任务、清空等待消息并开始新对话
/cancel       结束当前任务并清空等待消息
/status       查看 Codex 用量与额度窗口重置时间
/goal <目标>  为当前 Codex 会话设置持续目标
/help         显示此帮助

说明：/goal 需先发送一条普通消息以创建当前会话。
```

其中 `/goal` 需要已有普通会话的限制必须显示。

### 6.7 CommandResult 交付与失败矩阵

新增 `CommandResponder.SendStaticCard(ctx, ReplyTarget, CommandCard) CommandDelivery`：所有 command card 在序列化后限制 28 KiB、单次 10 秒；明确 card create/send 失败时至多发送一次等价 plain-text fallback。若 card/text 请求结果 unknown，则不发第二条可见消息，持久化 `reply_unknown` 和已知 message ID（或 null）。任何 duplicate receipt 不重放 effect 或 reply。

| 场景 | effect state / error code | 用户可见结果 | reply 持久化 |
|---|---|---|---|
| `/new` / `/cancel` 成功 | `succeeded` | 静态确认卡；旧任务卡由权威 Terminal 收尾 | card ID + `sent`；明确失败时 text ID + `sent` |
| interrupt grace 到期 | `failed/command_interrupt_timeout` | “停止请求超时，任务已按本地终止状态收尾。” | 同上；unknown 不重试 |
| companion stop 到期 | `failed/command_delivery_stop_timeout` | “停止交付超时，请稍后使用 /status 或 /new。” | 同上 |
| detached FIFO 条件更新失败 | `failed/command_queue_persist_failed` | “队列状态未能安全更新，未执行后续消息。” | 同上 |
| `/new` archive 失败 | `failed/command_archive_failed` | “未能安全开启新对话，当前会话保持不变。” | 同上 |
| `/status` 部分/全部账户失败 | `succeeded` / `failed/status_unavailable` | 可用字段加“暂不可用”，或全部不可用的固定卡 | 同上 |
| 无 Thread / resume 失败的 `/goal` | `failed/goal_session_unavailable` | “请先发送一条普通消息以建立或恢复会话。” | 同上 |
| `goal/set` 成功/失败 | `succeeded` / `failed/goal_set_failed` | “长期目标已设置”或固定安全失败 | 同上，绝不含 objective |
| 无效语法/未知命令 | `failed/command_invalid` | 固定错误卡和 `/help` 引导 | 同上 |
| card 与唯一 text fallback 都明确拒绝 | effect 保持原结果；`failed/command_reply_rejected` | 无可见结果，不再发送 | `feishu_bot_message_id=NULL`、`command_reply_outcome=rejected`；duplicate 不重试 |

命令的 effect 与 reply 分开持久化：`command_effect_state=succeeded` 后若回复未知，重试 event 仍只返回 duplicate，不重复 effect；恢复过程只可在已有记录证明此前**没有可见发送**时补发 text，不得补发 unknown card。`messages.status` 仅在确认可见结果后变为 `succeeded`；明确没有可见结果的 terminal failure 变 `failed` 并保存上述 error code。

## 9. Definition of Done

- [ ] 五命令的 parser、参数错误、receipt 去重和确定性用户卡有测试；`/stop` 仅保留兼容测试。
- [ ] `/new`/`/cancel` 通过 Worker-owned control API 清空等待 FIFO、条件终结被清除消息、取消 active Turn/delivery，并在 interrupt/delivery/DB failure 时按 CommandResult 矩阵有界收尾，保持跨频道/App 隔离。
- [ ] `/new` 遵守 archive 成功后 CAS clear、普通消息懒创建 Thread；`/goal` 在无 Thread 或 resume 失败时绝不创建 replacement Thread。
- [ ] `/status` 使用真实账户字段，正确转化 `resetsAt` 到 `Asia/Shanghai`，不泄露账户数据且不被长 Turn 阻塞。
- [ ] 每条普通文本以持久化 `received_at` 得到唯一 `<now>`；命令/goal/status 不被 formatter 污染；`/goal` 明文不出现在 MySQL、卡片、日志、Langfuse、workflow 或 timeline。
- [ ] forward-only migration、配置模板、README、HLD、本 Story、Story List 同步；`gofmt`、`go vet ./...`、目标 race 与 `go test ./...` 通过。
- [ ] S06-LI-01 在新进程完成 L3/L4，保存脱敏证据；外部依赖缺失时保持 In Development 并记录责任人/缺口。
- [ ] 独立技术架构、质量/安全、产品架构评审完成；blocker 修复且 blocker-only 复审后，才可 Delivered。
